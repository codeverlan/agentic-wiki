Coordination Rules

  • Use external capabilities when project needs exceed built-in plugin surfaces.
  • Use external capabilities autonomously only inside active project authority, development/local boundaries, and existing supervision rules.
  • Stop or queue supervision for credentials, production changes, publishing, personal-account actions, broad computer-use, sensitive data access, or unclear authorization.
  • Use project-local env files, JSON files, process environment, or approved ephemeral chat credentials for auth; never embed credential values in plugin files or durable artifacts.
  • Do not require a standardized credential payload because each capability can use provider-specific auth.
  • Capture every external invocation in a worker report or dedicated external-capability result packet.
  • Accepted result packets are immutable; corrections create superseding result packets linked to the prior accepted packet.
  • Programmed dashboards show external connection presence and status while omitting credential values.
  • Record expected-unavailable capabilities as affected-slice blockers with chat notification.
  • Record useful nonexistent capabilities in the future-resource queue instead of blocking work with available substitutes.
  • External capability work delegated to agents requires a slice-local worker report before coordinator acceptance.
  • External capability use must preserve authority, credential, supervision, privacy, and evidence boundaries.
