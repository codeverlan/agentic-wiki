Decision ID Question Accepted answer Implementation consequence Surface
AD-001Should incident/exception logs be append-only?Yes.Accepted entries are not edited in place. Corrections create superseding entries with links to prior entries.incident-log; validation-contract; delivery-workflow
AD-002How long should incident logs be retained?Project-local default retention with no automatic deletion.The plugin preserves logs unless the user explicitly directs retention, archival, deletion, redaction, or rotation rules.incident-log; accepted-decisions; retention policy
AD-003Should PHI-aware projects use stricter incident logging?Yes.Metadata-only logs, no PHI or secrets, monitoring phases, regular scan reminders, and abnormal-behavior review.incident-log; HIPAA-aware monitoring
AD-004Must intake ask whether the app handles PHI?Yes, mandatory.This is a preflight question before unattended continuous development.intent-packet; preflight readiness
AD-005Is HIPAA support legal certification?No.The plugin tracks HIPAA-aware development safeguards, not legal attestation or compliance certification.HIPAA docs; incident-log
AD-006Should the plugin be project-agnostic?Yes.It should support WordPress, web apps, CLIs, clinical tools, data workflows, and future project types through archetype-specific intake.archetype registry; storage adapters
AD-007Should BMAD be required?No.The plugin is BMAD-aware but not BMAD-dependent. Use the BMAD adapter when _bmad exists and the lightweight Agentic Wiki adapter otherwise.storage adapter model
AD-008Should project-specific guidance mutate the plugin?No.The plugin stays immutable unless an explicit plugin-development workflow starts. Project customization lives in local memory overlays.plugin-project boundary; overlay
AD-009Should overlays be able to broaden autonomy?Yes, within higher-priority boundaries.Project-local rules can enable needed skills, tools, and resources as long as safety, repo, user, and system constraints permit it.project overlay; instruction precedence
AD-010What is the primary plugin input?Intent packet from interview, existing specs/resources, or hybrid intake.The plugin normalizes all entry paths into project-local JSON plus HTML intent packet.intent packet
AD-011Should intake depth vary?Yes.Support quick start, standard preflight, and deep spec. Unattended continuous development requires at least standard preflight.intent packet; preflight
AD-012Should questions adapt by project type?Yes.WordPress, web app, clinical workspace, CLI/library, and other archetypes receive different question paths.archetype registry
AD-013Should visual/design work be part of intake?Yes when material.Use image generation, design skills, HTML mockups, or user assets to present selectable directions.design-assisted intake
AD-014Should milestone check-ins block unattended work?No, advisory unless a safety or stop boundary applies.The plugin suggests check-ins, but continuous work continues if the user has authorized unattended development.handoff; run modes
AD-015Should continuous runs create new slices autonomously?Yes.The coordinator may create and assign safe new slices without user approval inside the accepted scope.slice queue; task graph
AD-016What is the max parallelism default?Coordinator plus up to six workers.Workers own narrow slices; the coordinator owns shared control artifacts.agent topology
AD-017Who mutates shared control artifacts?Coordinator only.Workers propose queue, log, or overlay changes through worker reports.agent topology; worker reports
AD-018What happens when slice A blocks?Continue independent slice B.The blocked slice is recorded; dependent slices wait; independent work continues.blocking policy; slice queue
AD-019Should agents exhaust resources before blocking?Yes.Use local repo/tests/docs, official docs or web, browser tools, skills/plugins, subagents or review, then split or fallback.blocking policy
AD-020What if an expected tool is unavailable?Stop affected slice and notify in chat.If a resource should exist but is unavailable, affected slice blocks while independent slices continue.resource gap handling
AD-021What if a useful resource does not exist yet?Continue and record a future opportunity.Add to the simple chronological future-resource queue; advisory only.future-resource queue
AD-022How should credentials be handled?Development-pragmatic, best-effort non-persistence.If the user provides a credential in chat, use it for the approved task and avoid storing, echoing, or logging it.credential policy
AD-023Are project-local credential files allowed?Allowed when needed, never plugin-owned.Env, JSON, process env, and provider-specific formats are allowed; durable artifacts record metadata only.external capabilities; credential sources
AD-024Should external capabilities be first-class?Yes.Plugins, skills, APIs, MCP servers, browser tools, services, local tools, and spawned agents can be used inside authority.external capability registry
AD-025Should external capability results be auditable?Yes.Capture in worker report or JSON/HTML result packet; accepted packets are immutable and corrections supersede.external capability result packets
AD-026Should dashboards be supported?Optional but supported.Prepare bounded dashboard data and call visualization plugins/tools when requested. Dashboards show status, tasks, agents, tokens, logs, and external connections.dashboard data contract
AD-027What happens when the user returns?Do not automatically interrupt safe work.Append and prioritize the supervision queue at the next reasonable stopping point.supervision queue
AD-028How should status reporting work during unattended runs?Local artifacts first.Chat is reserved for blockers, safety boundaries, repair exhaustion, supervision tasks, whole-run stops, or requested summaries.status lanes; handoff
AD-029How should PR workflow behave?Non-blocking audit and sync artifact.PR approval should not halt continuous development unless user, repo, or platform policy requires it.delivery workflow
AD-030What is the validation repair policy?Two bounded self-repair attempts.After the second failure, stop affected slice, preserve evidence, and continue independent slices.validation contract
AD-031Is a high-risk review gate required?Yes.PHI/privacy, credentials, public API, schemas/storage, plugin-core, generated docs, security, and deployment require review or adversarial check.high-risk review gate
AD-032Should generated docs and schemas stay aligned?Yes.Code changes affecting commands, schemas, workflows, storage, or validation update docs and pass docs check.docs governance
AD-033How should handoff and compaction be handled?Durable HTML handoff required.Generate run-state and handoff digest at stops, stale leases, compaction risk, and user return.run-state; handoff digest
AD-034Should there be a branch ledger?Yes, a living HTML table.Track branch name, last updated timestamp, and brief contents description.branch ledger
AD-035When should future plugin packaging happen?Later, after decisions are integrated.Use plugin-creator only after scope and interview are complete and project-local decisions are durable.plugin-development boundary
AD-036Should the plugin own every future feature?No.It should coordinate external capabilities rather than hard-code every dashboard, browser, API, or workflow model.external capability coordination
AD-037Should logs include token and platform usage?Yes when available.Track token and platform usage in dashboard/status data if accessible; leave blank when unavailable.dashboard data; run-state
AD-038Should current project artifacts become reusable defaults?Only after an explicit plugin-development step.Project-local decisions can inform plugin candidates, but plugin files remain untouched until approved.plugin improvement queue; plugin boundary
