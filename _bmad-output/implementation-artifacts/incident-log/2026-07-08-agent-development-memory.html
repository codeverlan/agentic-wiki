PHI/HIPAA Safeguards

Metadata-only log for PHI-relevant software development; not legal certification.

This incident log is metadata-only. It records event identifiers, timestamps, severity, evidence pointers, and review actions; it must not store PHI, credentials, secret values, tokens, passwords, or raw sensitive text.

Monitoring Phases

For PHI-capable projects, use these phases to remind the user to run regular security scans and monitor abnormal behavior that may indicate leakage of information, credentials, plans, or PHI.

Phase ID Cadence Reminder Evidence User action
preflight-security-baseline before unattended continuous run or release Run dependency, secret, static analysis, and access-control checks. scan report path and reviewed access-control notes Confirm baseline security posture before PHI-capable development proceeds.
implementation-monitoring during implementation slices Monitor logs, audit events, and unexpected file or network activity for abnormal behavior. metadata-only audit summary Review possible information, credential, plan, or PHI leakage indicators.
recurring-security-scan monthly or before release Run dependency, secret, static analysis, and access-review checks. scan report path Review abnormal behavior and possible information leakage.
incident-response-review when an incident or suspicious event is recorded Preserve metadata-only evidence and escalate user-supervised response. incident ID, timestamps, hashes, and evidence pointers Decide containment, notification, credential rotation, and follow-up review steps.

Append-Only Boundary

Accepted entries are append-only. Corrections should be recorded as superseding entries instead of rewriting history, so unattended agent work leaves a durable trail of abnormal conditions and user-supervision needs.
