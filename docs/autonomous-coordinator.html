Autonomous Development Coordinator

A provider-neutral, durable execution engine for unattended software delivery. Agentic Wiki supplies the memory, provenance, HTML projections, and policy boundary; the coordinator adds scheduling, workers, recovery, integration, and completion proof.

Operating Contract

  • Continue until the complete build and its tests pass. Milestones and implementation groupings are not stop conditions.
  • A blocked slice affects only its descendants. Independent or enabling slices continue.
  • At most six workers run concurrently, with explicit path ownership, assignments, leases, acknowledgements, and fencing tokens.
  • The coordinator alone mutates shared run state and canonical project memory. Workers return bounded reports and evidence.
  • User return prioritizes the chronological supervision queue at a reasonable stopping point without cancelling safe active work.

Project Adaptation

BMAD projects store coordinator artifacts beneath _bmad-output/implementation-artifacts. Other projects use .agent-development/implementation-artifacts. Project-specific rules, decisions, design memory, credentials, and mutations remain in project memory. They may alter plugin guidance at runtime but never mutate the reusable plugin source.

Security and Privacy

Credential references resolve from project-local environment or ignored JSON sources and values are never written to coordinator artifacts. Computer use requires supervision. When PHI handling is yes or unknown, development evidence is synthetic-only; PHI operations require an OperationContext, and remote adapters, cloud storage, telemetry, external PHI invocation, and static PHI export are denied.

Completion

Completion requires every required slice integrated, tests passing at the integrated revision, no mandatory blocker or supervision request, no reachable or discoverable work, reconciled budgets, current projections, and complete evidence hashes. The result is a content-addressed immutable manifest, not a phase declaration.
