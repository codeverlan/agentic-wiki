Coordinator Agent Compatibility

The coordinator can discover, qualify, select, invoke, supervise, and record work from Codex and ChatGPT surfaces without making either product part of its core execution model. Public and personalized private agents share one provider-neutral contract; availability never implies authority.

Agent Registration

Register a stable agent ID, display name, product, public or private visibility, publisher, portable source URI, discovered version, integrity and trust states, and one or more surfaces. Each surface declares kind, operations, and callable or handoff_only execution mode. Reject identity collisions, source spoofing, embedded credentials, and silent version drift.

Public registration requires attributable publisher and source metadata. Private registration may prefer a personalized agent for project-specific work, but that preference is project memory, not a mutation of the reusable agent or plugin.

Private-agent immutability: projects may change selection preferences, context, assumptions, output admission, and guidance in project-local memory. They must not rewrite private plugin source, hidden prompts, manifests, or installed cache contents unless the user explicitly starts a separate plugin-development task.

Adapter Authoring Contract

  1. Implement metadata-only discovery first. Discovery must not invoke the agent, read credential values, or assert unsupported capabilities.
  2. Map product-specific surfaces into stable descriptors with portable source references, discovered versions, schemas, authority, execution mode, and availability.
  3. Implement callable and handoff-only paths separately. A handoff creates supervision work and never emits a successful execution receipt.
  4. Use durable lifecycle receipts: planned, started, waiting, succeeded, failed, timed out, cancelled, or outcome unknown. Bind receipts to agent and surface versions, input hash, correlation ID, and causation ID.
  5. Make retries idempotent. An uncertain external outcome requires reconciliation or supervision, not duplicate execution.
  6. Return bounded, schema-validated, recursively redacted output. Admit claims or decisions to memory only after provenance, privacy, and stale-context checks.
  7. Add deterministic fake-host conformance tests for outages, authorization expiry, schema drift, duplicate replies, restart equivalence, and extension without core changes.

Qualification Checklist

AuthorityGranted authority is no broader than the slice requirement; delegation cannot increase it.

Data policyResidency, retention, telemetry, PHI eligibility, disclosure labels, and context scope satisfy project policy. Unknown sensitive policy is denied.
OperationsCost, latency, supervision, reversibility, replayability, and callable authorization satisfy the requirement.
FallbackEvery fallback is independently qualified; failure remains slice-local and cannot bypass policy.

Context and Memory Admission

Package only the sources needed for the assigned operation. Bind source hashes, content hash, disclosure labels, qualification identity, and freshness to the context bundle. Quarantine prompt-injection material. Agent output may enter drafts, evidence, decisions, design records, or claims only through provenance-backed admission; output is never canonical merely because an agent produced it.

Supervision, Credentials, and PHI

Computer use, irreversible or destructive actions, publication, financial effects, expanded authority, and other mandatory categories require an exact-invocation supervision grant. Delegation cannot bypass that gate. User return prioritizes waiting supervision at the next safe boundary without cancelling safe active work.

Credentials remain project-local references resolved only for the child invocation and recursively redacted from evidence. For projects that handle PHI, use synthetic data for development. A remote or external agent is ineligible for PHI unless the strict clinical policy explicitly permits the operation; unknown PHI status defaults to the restrictive policy. Never place PHI in prompts, fixtures, logs, screenshots, HTML, or Git.

SEO Decision Lab Worked Example

Use the portable private-plugin URI plugin://seo-decision-lab@personal/. Discovery currently resolves version 0.1.0+codex.20260705181758; operators must use the version discovered at runtime rather than relying on this example.

  1. Discover the plugin, its SEO skill, and local MCP surface without invocation or credential reads.
  2. Register personal/seo-decision-lab as a private Codex agent and qualify the requested DataForSEO operation.
  3. Check dfs_auth_status and dfs_account_status through the MCP. Store only redacted status and cost provenance.
  4. Prefer a matching shortcut such as dfs_labs_keyword_ideas, dfs_google_serp_live, or dfs_backlinks_summary; use dfs_request only for documented operations without a shortcut.
  5. Record domain, intent, market and language assumptions, request hash, discovered profile version, portable MCP reference, usage, and result provenance. Default assumptions are United States, location code 2840, and language en, and must be visible as defaults.
  6. If authentication is absent, block only the SEO-dependent slice. Continue independent work and use only independently qualified fallbacks permitted by project policy.
  7. Admit the result as evidence or a proposal after redaction, schema validation, context freshness, and provenance checks.
